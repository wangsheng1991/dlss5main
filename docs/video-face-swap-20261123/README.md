# 把自己换进视频当主角：技术可行性与边界（2026-11-23）

> 触发：王胜看视频时提出「把自己换到视频中当主角」，并希望用在游戏场景里。
> 本文分两部分：**我们现在能给的判断**（可对外说）与**必须实测才能定的部分**（要问 Windows 那台机器）。
> 约定：标「已知」的是开源项目公开信息；标「未核实」的必须跑过才写进宣传。

## 一、一句话结论

**「把脸换成自己」在离线短视频上是成立的，且已有成熟开源方案；「把自己整个人替换成游戏角色」是另一个量级的问题，现阶段只能做到片段级、正脸/半侧、短时长。**

不要把两者混成一句「AI 换脸」对外讲，否则客户拿一段第三人称快速转身的游戏实机来，必然翻车。

## 二、三类需求，难度差三个数量级

| 类型 | 输入 | 输出 | 现状 | 用在游戏场景 |
| --- | --- | --- | --- | --- |
| A. 视频换脸 | 一段视频 + 一张自己的正脸照 | 同一段视频，脸换成自己 | **成熟**，开源可跑，离线几分钟 | 游戏过场、主播出镜、角色自拍 |
| B. 角色替换（全身） | 一段动作视频 + 一张角色图 | 角色按动作重演，或把视频里的人换成角色 | **前沿**，能跑但重（24GB 级显存） | 把自己"演"成游戏角色 |
| C. 实时换脸 | 摄像头/直播流 + 一张脸 | 实时画面换脸 | 能做，质量低（128 源） | 直播露脸、连麦 |

王胜说的「把自己换到视频中当主角」，字面上是 A + 部分 B。**先做 A，验证效果与客户接受度，再谈 B。**

## 三、可选的开源方案（已知，公开信息）

| 方案 | 做什么 | 许可/注意 | 显存（估计，未核实） |
| --- | --- | --- | --- |
| **FaceFusion** | 视频/图片换脸全家桶：换脸、换头、口型、年龄、修复 | 代码 MIT，但内置模型许可各异（inswapper 系为非商用） | 4–8 GB 可跑，开增强更高 |
| **Deep-Live-Cam** | 单图实时换脸（摄像头/视频） | 代码开源，模型同上 | 4 GB 级 |
| **InsightFace `inswapper_128`** | 底层换脸模型，128×128 对齐 | **模型权重非商用**，这是最大的合规红线 | 2–4 GB |
| **LivePortrait**（快手） | 表情/头部动作迁移，不换身份 | 开源，可商用（需核对版本） | 6–12 GB |
| **Wan-Animate**（阿里 Wan 系） | 参考角色 + 驱动视频 → 角色按动作重演，支持角色替换 | 开源，权重许可需核对 | **24 GB 级** |
| **VACE**（阿里 Wan 系） | 视频编辑一体机，参考换人/换背景 | 开源 | 24 GB 级 |
| **MimicMotion / MusePose / Champ** | 姿态驱动人像动画 | 开源 | 12–24 GB |

**合规红线**：`inswapper_128` 的权重是非商用许可，直接拿它做付费功能有风险。要么换成许可干净的模型，要么只做站内演示不收费。这一条必须先定，再谈产品化。

## 四、游戏场景为什么难（这是要重点讲的）

1. **头部角度**：换脸模型在正脸/半侧（±30°）最好；第三人称游戏里角色经常侧身、背对、低头，角度一大就糊或换不上。
2. **遮挡**：武器、手、头发、护甲挡脸时，模型会把遮挡物一起"换"进脸里。
3. **运动模糊与快速剪辑**：游戏实机镜头运动快，逐帧对齐会抖。
4. **画风错配**：写实人脸贴到风格化/卡通渲染的角色上，会进"恐怖谷"。这是**审美问题，不是技术问题**，修不好。
5. **光照**：游戏内打光（尤其夜景、彩色环境光）与人脸参考图的光照不一致，需要调色/重打光。
6. **身份一致性**：同一段视频里，脸要每一帧都是同一个人；换脸模型逐帧独立推理，容易出现"每帧像不同的人"。

**能承诺的**：正脸/半侧、脸部占画面足够大、镜头相对稳定、5–30 秒片段。
**不能承诺的**：大角度、快速转身、全遮挡、多人同框、实时高质量。

## 五、分阶段落地

**阶段 1 · 离线验证（1–2 天，只花 GPU 时间）**
- 拿一段 10 秒游戏过场 + 一张正脸照，用 FaceFusion 跑一遍换脸。
- 产出：一段 before/after 对比视频。
- 判据：脸是否每帧都是同一个人、角度极限在哪、客户看了觉得"像不像"。

**阶段 2 · 变成可交付形态（如果阶段 1 成立）**
- 正好补上视频线缺的"收货口"：上传视频 → 报价 → 处理 → 下载。
- 注意：**这一期只收意向、不收钱**，先把流程跑通（见 `docs/VIDEO-DLSS5-STRENGTHENING-20261123.md`）。

**阶段 3 · 全身角色替换（重）**
- 走 Wan-Animate / VACE，需要 24GB 级卡。
- 在此之前不做任何对外承诺。

## 六、GPU 机器的家底（2026-11-23 已实测，详见 `RESULT-GPU.md`）

本机是 Intel Mac，AMD 4GB 显存，**跑不了任何换脸模型**。那台 Windows 已实测：

- **RTX 4090，24 GB**，驱动 591.86 / CUDA 13.1——硬件够。
- **但卡正被占用：20617 / 24564 MiB、利用率 37%**，只剩约 3.9 GB，现在跑不了大模型。
- Python 3.12.8，但 **PyTorch 是 2.8.0+cpu**，CUDA 不可用；需重装 CUDA 版。
- 无 ComfyUI / FaceFusion；外网通（GitHub、PyPI 均 200）。
- 磁盘空闲：C 45.6 / D 22.6 / E 74.7 / G 86.8 GB。
- **250/251 井道当前不可用**：两条隧道 down，img3d 返回 502。

仍然缺的只有一个数：**10 秒 1080p 换脸要跑多久**——要等卡空出来、装好环境才能测。

## 七、给王胜的两句话

- **这件事能做，但只能做"片段级、正脸、离线"**，别对客户说成"实时把我变成游戏角色"。
- **卡不在算法，在卡的档期**：那台 4090 现在被别的任务占着 20.6 GB，换脸要先排队，或者等占用它的任务让路。
