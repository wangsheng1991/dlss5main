## 本次处理

- 保留既有 GA4，将已登录用户的报价曝光、方案点击、上传、生成、结果下载、结账跳转/失败/返回同步到经过鉴权的第一方记录。只允许枚举维度，不收图像、提示词、邮箱、文件名、完整 URL；服务器按自身认证 uid 关联。
- 生成提交异常单独记为 generation_request_error（积分不足/限流/验证/上游/网络），不会冒充已完成任务的失败。事件 UUID 幂等、每账号每日最多 200 条；记录失败不阻塞产品。不补写历史事件，不用返回成功页冒充付款。
- 服务端记录所有 Waffo checkout 的响应分类和耗时，区分准备好付款页、已有订阅/订单阻止、未登录、配置或支付方错误。财务状态继续以原有验签 webhook 与账本为准。
- 修复一个可复现的入口问题：匿名用户在报价页点击订阅，原 `/login` 登录后默认回工作台；改为 `/login?next=%2Fpricing`，保留购买上下文。没有改价格、积分、订阅规则或首页。
- `expiresAt` 是清理标记，未开通新的 Firestore TTL 策略；不能声称已自动删除。

## 如何复查

在项目目录用安全本地环境运行：`node scripts/conversion-readout.mjs /absolute/private/output.json`。仅读取数据库与站主 UID，输出汇总；不调用 GSC/GA4，不发送客户邮件，不创建订单、不改余额。

新增观察路径：成功任务账号 → pricing_view → plan_select → checkout 服务端结果 → checkout intent → 验证付款。各阶段看独立账号，不能将事件数直接作为人数；上传有多参考图时会有多个事件。匿名访客仍依赖现有 GA4；第一方记录只覆盖已登录人群，也可能因离线/关闭页面漏报。

下一步决策依据：成功出图的人很少到报价页，优先补购买价值/入口；方案点击很多但服务端拒绝，优先修阻断原因；已拿到付款 URL 却不付款，才深入支付页与支付方式；不能凭行业平均数指定其中一种。当前不更改付费墙或承诺效果。
