# 视频对比的呈现方式：学 Loop Forge，落到我们站上（2026-11-23）

参考：https://loopforge.cc/projects/video-upscaler/

## 它做对了什么

1. **一句话把结论钉死**：「Eleven upscalers on the same five clips, every output at exactly 2x.」——方法数、素材数、倍率三个数直接摆出来，不留解释空间。
2. **对比是可操作的，不是一张图**：一个大画面，左右两路同源视频叠放，中间一条可拖拽的分隔线。拖到哪，就比到哪。
3. **角标直接标成本**：左上 `Lanczos resize / NO GPU`，右上 `SeedVR2 3B int8, 21 frames / 12 GB VRAM GPU`。**「同样效果、更少显存」这句话不用写，用户自己看出来。**
4. **三个层级的控件**：先选素材（Face / Detail / Particles / Graphic / Dance），再选视图（Split / Grid），再选放大（Fit / 2x / 4x）。想粗看就粗看，想抠像素就抠像素。
5. **同一帧、同一区域**：切换任何一路，播放位置和取景都不变；放大时所有面板同步平移，防止「两边看到的不是同一块」。
6. **敢写自己失败的地方**：正文里有「SeedVR2 7B int8 输出黑帧」「12 GB 卡上默认分块崩掉」这类小节，再附「Wall time, every cell」的耗时矩阵。可信度来自这里，不是来自形容词。

### 顺手修掉的一个坑

原来那份 `neon-bicubic.mp4` 是从别的来源来的，构图与 `reference` / `candidate` 不一致（画面被缩小、四周留边），直接叠放会比错位置。已按标准做法重建：

```
ffmpeg -i <scene>-reference.mp4 -vf "scale=640:360:flags=bicubic,scale=1280:720:flags=bicubic" ...
```

即「同一份高清参照 → 降到 360p → 双三次放大回 720p」，这样左右像素级同构图，对比才成立。产物：`<scene>-bicubic-aligned.mp4` 与对应海报。

## 上线真实视频模型时，四件套必须先备好

1. **同源素材**：同一段原片，每条线路都从它出发；每条线路的输出必须同构图、同帧数、同帧率（用 ffprobe 校验，别信肉眼）。
2. **两个角标**：方法名 + 真实成本（显存 / 是否用卡 / 处理时长）。成本不给出来，对比就只是截图比赛。
3. **耗时矩阵**：每一格都填，包括我们输的那些格。空格比慢数字更伤信任。
4. **一个能承认的缺点**：写清什么镜头我们会失败（大角度、快速运动、遮挡、风格化角色）。写了，用户才信别的部分。

## 不许做的事

- 不许拿「高清参照」当我们的成品展示；参照只能标成参照。
- 不许只放一张好看的静帧；必须能连续播放。
- 不许在能力未上线时用这套对比做对外承诺——`/vs/...` 目前是 `noindex`，正式上线前换成成片对照。
- 不许把「同样的效果、更便宜」写成形容词，只给数字和角标。

# 三类对比，一套逻辑

视频、3D 重建、贴图，本质是同一个问题：**同一个输入，两种处理，同一个视角，可操作地切换。**

差异只在「同一个视角」怎么保证：

| 类型 | 视角是什么 | 怎么切换 | 难点 |
| --- | --- | --- | --- |
| 视频 | 时间点 + 取景 | 拖分隔线 / 拖时间轴 | 两路必须同帧同构图、同步播放 |
| 3D 重建 | 相机位置（绕物体旋转） | 拖拽旋转，两路相机同步 | 两路模型必须同尺度、同朝向、同背景 |
| 贴图 | 相机角度 + 缩放 | 固定角度下拖分隔线 + 放大 | 两路必须同 UV、同光照、同分辨率基准 |

## 3D 重建对比

**目标形态**：同一个物体，左边低模/低质重建，右边高质重建；拖一下，两个模型同时旋转到同一个角度；再放大，看边缘和拓扑。

**两种实现，按成本排序：**

1. **预渲染环转（无依赖，先做这个）**
   - 每个方法绕物体固定拍 24–36 个角度，导出同尺寸序列帧。
   - 前端用拖拽控制「角度索引」，两路同步换帧；本质是视频对比的变体，复用同一套拖拽逻辑。
   - 优点：不用 WebGL、没有加载模型的开销、手机也不卡。
   - 缺点：不能自由旋转，放大上限受单帧分辨率限制。

2. **真 3D 同步相机（要做「自由旋转」时）**
   - 引入 `three` + `GLTFLoader`（glb），或 Gaussian Splatting viewer（ply/splat，TripoSplat 的产物是后者）。
   - 一个 `OrbitControls` 驱动两路 `camera`，两份模型放在同一原点、同一尺度。
   - 对比模式三选一：并排 / 叠加（A/B 淡入淡出）/ 差异热力图。
   - 代价：bundle 增加约 600 KB，移动端要降采样、限制帧率。

**素材规范（必须先定，否则做出来不能比）：**
- 同物体、同朝向、**同尺度**（用同一个包围盒归一化）。
- 同背景（透明或同一环境图），否则用户分不清是模型好还是布光好。
- 每条线路标注：重建耗时、显存、输入图片张数。
- 保留原始输入（那几张照片），放对比旁边——用户要看到「从什么变成什么」。

**当前阻塞**：`taobao3d`（Windows 7861）SSL 断、`img3d` 返回 302/502、250/251 井道仍 down，暂时拿不到真实 3D 产物；站内也没有 three.js 和任何 `.glb/.ply` 素材。

## 贴图对比

**目标形态**：同一个模型、同一个角度、同一束光，左边原贴图，右边高清/修复后的贴图；拖分隔线看接缝，放大看纹理。

**关键约束：**
- 两路必须同 UV、同相机、同光照——**只让贴图这一个变量变**，否则比的是渲染而不是贴图。
- 放大到 2x/4x 时要能看出：文字边缘、布料纤维、金属划痕、接缝处的拉伸。
- 平坦色块上看不出差别，必须选**有细节、有文字、有高频纹理**的角度。

**实现**：复用图片对比的拖拽逻辑（站内已有 `src/components/ImageSlider.tsx`），补三样：
1. 缩放档位（1x / 2x / 4x），两路同步平移；
2. 左右角标写贴图规格（如 `1024² · 原图` vs `4096² · 重绘`）；
3. 多角度切换（正面 / 45° / 近景），每个角度一组同源图。

**素材规范**：每个角度一对图，文件名带角度和版本；图必须是同一裁切，不能一张宽一张窄。

## 什么时候做哪一类

1. **视频**：已落地，等真实模型结果换右路。
2. **贴图**：只要有成对图片就能做，不依赖 3D 服务——**这是下一个能立刻推进的**。
3. **3D**：等 250/251 恢复、拿到 triposplat 的真实产物后，先做「预渲染环转」，确认交互有用再考虑上 WebGL。
