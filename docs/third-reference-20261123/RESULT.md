## 结论

**1. 上游接受三张图。** 两组三图任务都是 `SUCCESS`，11–13 秒出图，与两张图同一量级。没有 400，没有降级。

**2. 第三张图确实改变了场景，而且连机位一起带过去。** A 是阴天街边的平视半身；B 直接变成了仰拍、玻璃幕墙、白天、站在广场上——第三张图是仰拍建筑，成品也仰拍。所以「第三张只提供环境与构图」这句提示词是有效的。

**3. 显式机位会改动取景，但不能完全压过参考图的角度。** C 加了 `full_body`，明显比 B 露出更多身体（到大腿、脚下有地面），但画面仍然是那个仰角。写进提示词的「显式机位优先」是**部分成立**，不能对客户承诺「选了机位就一定不受参考图影响」。

**4. 最大的问题不是场景，是角色身份——而且三张图让它更明显。** 三组里角色的脸没有一次是参考图给的（本来就背对镜头），而且造型还会跑：A 是女性、板甲；B 和 C 变成了男性、皮夹克/战术服。**这坐实了素材板上的那条：库里缺一张角色正脸，是今天最贵的缺口。** 在这一步补上之前，任何页面都不能承诺「角色的脸会被保持」。

**5. 有正脸的参考确实能用上：** D 组把 ② 换成一张正脸人像，成品右边的人就是那张脸的类型（深色长发、白 T 恤、柔和轮廓），而不是 A 组那种被编出来的脸。**所以「库里的角色参考没有正脸」这条缺口是实打实的、也是补得回来的。**

**6. 但真正的问题比「哪张参考有没有脸」更糟：两张图里通常只保住一张脸，而且保哪一张不稳定。** D 组里 ① 号位（`you.jpg`，一个扎马尾的女生的正脸）变成了**男性**、丸子头；A 组里 ① 号位是保住的。同一份提示词、同一个 seed，只换了 ② 号图，被替换的却是 ① 号位。这说明「每张脸都按参考保持」这句话在产品上**不能当承诺**，只能是「尽量」。下一步该做的不是再加参考图，而是**生成后做一次身份核对**：把两张参考缩略图和结果并排放出来，让人一眼看出「哪张脸被换掉了」。

## 边界

- 三组都是**直连上游**跑的（`ALPHANET_API_KEY`），没有经过站点 UI、没有花用户额度、没有写入任务库。请求体与 `buildToolTask` 的输出一致，但「登录状态下第三槽点击上传」这一层仍只有单测覆盖。
- 用的都是我自己的参考图，没有官方游戏素材；第三张是站内自己的建筑照片。
- 三张结果的版权按站内口径处理（自有素材生成的图），可以进推广素材库；但**不能**用来展示任何游戏角色。
